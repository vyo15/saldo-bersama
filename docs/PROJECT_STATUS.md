# Project Status

Dokumen ini adalah snapshot kondisi project sekarang, bukan jurnal perubahan.

## Runtime canonical

- **Frontend:** React 19 + Vite 7 PWA.
- **Backend:** Vercel Functions.
- **Database/source of truth:** Turso/SQLite HTTP pipeline.
- **Auth desktop dan mobile:** tombol Google branded Saldo Bersama memakai contract UI yang sama, tetapi transport production dan development dipisah pada loading boundary. Pada production canonical `saldo-bersama.vercel.app`, tombol siap melalui module server-OAuth ringan tanpa mengunduh Firebase browser Auth, lalu browser memulai Google OAuth Authorization Code flow ke `/api/auth/google/start`; callback server memverifikasi signed `state`/`nonce` + PKCE S256, menukar code menjadi Google ID token, menukarnya lagi melalui Firebase Identity Toolkit menjadi Firebase ID token, lalu memakai verifier Firebase + registry `users` canonical sebelum membuat registered HttpOnly server session. Localhost/device emulation lazy-load Firebase popup sebagai fallback development. Mobile menyimpan hanya flag presentasional bahwa onboarding pernah dilihat agar returning device langsung ke login; flag tidak menjadi authority dan onboarding dapat dibuka ulang. Tidak ada Firebase browser redirect state pada production.
- **Session/authorization authority:** signed HttpOnly session v2 membawa credential opaque; `user_sessions` + status/role/binding Firebase UID pada `users` adalah authority runtime. `ALLOWED_USERS_JSON` hanya bootstrap/recovery Administrator pertama. User dapat melihat/revoke session perangkat miliknya; role change/deactivation mencabut session aktif.
- **Google integration:** Apps Script bridge; Sheets mirror satu arah, Calendar reminder bersama, Drive backup teknis.
- **Abuse/operational health:** process-local limiter tetap lapisan murah, sedangkan bucket Turso v13 menjadi counter lintas instance untuk gateway/export/login/OAuth. Public `/api/health` tetap minim data dan merepresentasikan **core availability**: database/schema/binding, maintenance, serta integrity failure. Scheduler, integration dead-letter, notification/dead-letter, dan backup failure tetap muncul pada `system.health` terautentikasi sebagai operational warning dan tidak mematikan login/ledger ketika core sehat; partial Push delivery tetap mendegradasi scheduler heartbeat. External alert delivery tetap belum dipilih/diimplementasikan.
- **Active schema contract:** v16.
- **Kolaborasi Member v14 (dipertahankan pada runtime v16):** Member dapat mengajukan rekening/kategori baru dan transfer shared → personal melalui request backend; Administrator mereview dengan `row_version` + idempotency, dan approval transfer membuat tepat satu ledger canonical secara atomik. Transfer personal lintas pemilik diizinkan dengan ownership ledger mengikuti rekening sumber/debit.
- **Investasi manual v16:** aset investasi di aplikasi lain hanya **dicatat**, bukan dihubungkan sebagai broker/trading API; tidak ada credential broker, login broker, live price, auto-sync, atau order execution. Satu rekening `account_type=investment` menjadi RDN canonical; Buy/Sell mengubah RDN melalui cash-impact event investasi tanpa menjadi income/expense; weighted cost basis, manual valuation + last-trade fallback, realized/unrealized P/L, reconciliation as-of tanpa auto-adjust, Administrator-only correction, `row_version`, idempotency, backup/restore, dan integrity guard berada di backend. Route `/investasi` memakai bahasa Catat beli/Catat jual/Perbarui harga, hero total aset investasi tercatat, capability-driven quick action, Cash RDN, holding aktual, dan rincian per saham (lot/lembar, average cost, remaining cost basis, harga terakhir beserta sumbernya, nilai, realized/unrealized P/L, serta aktivitas buy/sell/valuation/opening-position/correction), inline validation/focus error, prerequisite guidance tanpa dead-end Member, dan same-intent retry guard untuk `OUTCOME_UNKNOWN`. Rekening Investasi menjadi pintu ke detail saham tersebut; Tambah/Tarik dana membuka Transfer composer agar Bank↔RDN tetap netral terhadap cashflow. Setup portfolio sengaja tidak meminta jenis setup, broker, atau nama portfolio wajib: user memilih rekening Investasi sebagai RDN dan boleh menulis label sumber catatan opsional seperti `Ajaib`; label tersebut hanya metadata manusia tanpa koneksi/sinkronisasi. Jika RDN belum ada, flow Rekening dibuka dengan jenis Investasi terisi otomatis lalu kembali otomatis ke setup portfolio. Draft pembelian dipertahankan ketika Cash RDN kurang; Transfer diprefill sebesar kekurangan dan kembali ke dialog pembelian. Onboarding existing investment memakai semantic opening position + Cash RDN awal, bukan fake Buy. Setelah Sell, Cash RDN menjadi state selesai dan penarikan hanya opsi. Rekening Investasi memakai nama canonical otomatis dengan qualifier opsional agar multi-RDN dapat dibedakan, ditambah label Pribadi, Pasangan, atau Bersama; Dashboard mobile/desktop memakai summary backend yang sama berdasarkan keberadaan `portfolios`.
- **Runtime DEV/PROD terisolasi:** `npm run dev` hanya bootstrap/menulis `.env.local`; `npm run prod` tidak menarik atau menimpa Development. Google bridge adalah grup pusat yang boleh diselaraskan DEV → PROD lokal hanya bila grup DEV lengkap dan PROD kosong; Turso/session/OAuth/VAPID tidak pernah disalin lintas environment. Aggregate health scheduler/integrasi boleh menjadi warning selama database/schema/frontend core sehat; integrity/maintenance/schema tetap blocker.
- Source v16 mempertahankan guard `DATABASE_ENVIRONMENT`/session v12 dan `rate_limit_buckets` durable untuk throttle lintas instance; binding database tetap fail-closed. Development dan Production sekarang merupakan dua runtime yang wajib terisolasi. ADR-0007 dipertahankan hanya sebagai catatan historis constraint satu-database; source/test aktif menolak database/token/session/VAPID yang dibagi lintas environment.

## Workflow saat ini

- Source terbaru + test aktual adalah sumber kebenaran.
- Tidak ada task card/Task ID/branch automation sebagai workflow wajib.
- Quality gate lokal canonical: `npm run verify`; `npm run zip` menjalankannya otomatis sebelum packaging dan pre-push guard menjalankannya lagi sebelum push. Handoff patch hanya berstatus final setelah gate tree final PASS pada Node 24.18.1; environment non-canonical wajib menyebut artifact candidate/unverified. Setelah setiap verification PASS maupun gagal, generated build/test artifact dan cache Vite generated dibersihkan tanpa menghapus dependency, `.env.local`, `.vercel`, atau Git metadata.
- Delivery rutin: commit pada `main` lalu `git push origin main`; pre-push memverifikasi ref/SHA aktual, clean working tree, fast-forward, full `npm run verify`, lalu schema/binding Turso Production secara read-only sebelum ref dikirim. Runtime schema baru tidak boleh terdeploy sebelum Production DB kompatibel; push tidak pernah auto-migrate. Quality GitHub tetap berjalan server-side.
- `npm run zip` tetap menjalankan full verification dan sekarang clean-only: PASS membuat `saldo-bersama-clean.zip` secara atomic; verification gagal exit non-zero dan tidak membuat archive baru. Clean ZIP verified terakhir tidak ditimpa oleh hasil yang gagal. Artifact `saldo-bersama-UNVERIFIED.zip` hanya historical input remediation dari workflow lama, bukan output workflow saat ini.
- Guarded/high-risk tetap membutuhkan approval eksplisit sebelum coding/operation.

- Service Worker v10 tetap network-only untuk `/api/*`; stable image memakai stale-while-revalidate sehingga asset publik dapat diperbarui setelah deployment tanpa menunggu cache lama habis.

## Notifikasi dan pengingat saat ini

- Tujuh pengingat otomatis existing tetap dijadwalkan server dan memakai dedupe canonical.
- Pengingat manual one-shot tersedia langsung pada Kebutuhan periode aktif, Alokasi Dana aktif, occurrence Jadwal Rutin yang belum selesai, dan Target aktif. Pengingat hanya milik actor, disimpan server-side, memakai `row_version`, idempotency, audit, dan diproses scheduler.
- Push produk memakai privacy-safe lock-screen: copy detail boleh tetap ada di queue server, tetapi transport Web Push hanya membawa tipe/id/target dan Service Worker menampilkan copy generik tanpa nominal, rekening, merchant, atau nama objek finansial. Logo aplikasi tetap dipakai sebagai `icon` dan badge monokrom khusus Android.
- Reminder manual menampilkan `lastDispatch` dari queue, menolak jadwal baru selama dispatch lama masih nonterminal, dan dibatalkan atomik saat entity selesai/ditutup/diarsipkan/dihapus; integrity check memeriksa drift user/entity/queue. UI memberi warning bila Web Push perangkat belum siap tanpa menganggap penyimpanan reminder gagal.
- Real-device Android/iOS/desktop tetap memerlukan QA operasional karena browser/OS menentukan bentuk final notification card dan lock-screen privacy.

- Tooling environment memisahkan dua profile yang wajib ada pada setiap workstation tepercaya: `.env.local` Development-only dan `.env.production.local` Production-only. `npm run dev` hanya auto-refresh Development dan tidak menyentuh `.env.production.local`; `npm run prod` tidak pull/menimpa `.env.local`, memvalidasi isolasi profile, boleh menyejajarkan hanya grup Google bridge pusat ke profile Production lokal yang kosong, memeriksa Turso Production read-only, lalu Vercel Production aktual agar keberhasilan Development tidak dianggap bukti Production. Core public health kini hanya memblokir database/schema/binding, maintenance, atau integrity failure. Scheduler, Google integration, backup, dan notification degradation tetap dilaporkan sebagai operational warning; `npm run prod` dapat membuka login/ledger bila core Production + frontend sehat sambil tetap menampilkan diagnosis tanpa membocorkan secret.
- Tooling environment juga menyediakan `npm run env:pull:development` dan `npm run env:status` untuk bootstrap/troubleshooting lintas-PC tanpa menyalin secret manual. Checker Production menjaga public Firebase/Google config tetap selaras dan menolak database/token/session/VAPID yang dibagi lintas Dev/Prod; fingerprint Web Push yang ditampilkan bersifat public-only.

## Open operational risks

1. GitHub `main` harus memblok force push/delete dan menjalankan workflow `Quality` pada push. Direct push normal dipertahankan untuk workflow private sederhana; jangan gunakan `--no-verify`.
2. Source sudah memblokir cross-environment database. Operasional tetap perlu menjaga evidence bahwa Development/Production menunjuk resource berbeda, tetapi ADR-0007 sudah berstatus Superseded dan tidak lagi menjadi blocker runtime.
3. Production schema/runtime parity dan resource Google nyata harus diverifikasi melalui runbook.
