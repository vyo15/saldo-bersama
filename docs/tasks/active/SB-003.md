## Objective

Menyederhanakan workflow menjadi tiga team (`COORD/FE/BE`), mengizinkan banyak task/tab paralel tanpa WIP limit selama Write Scope tidak overlap, membuat task approved selesai lokal tanpa menunggu PR/CI termasuk guarded yang sudah mendapat approval eksplisit, dan melonggarkan clean ZIP agar file/folder diagnosis aman dapat ikut untuk review ChatGPT tanpa membocorkan secret/dependency/build.

## Acceptance Criteria

- [x] Team canonical hanya COORD, FE, BE.
- [x] Status task dipangkas menjadi DRAFT, APPROVED, IN_PROGRESS, ON_HOLD, DONE.
- [x] Tidak ada WIP limit per team; parallelisme dibatasi oleh Write Scope overlap.
- [x] `task:finish` mendukung replace-first dari `main`, membuat/revisi branch task otomatis, lalu menangani commit, sinkronisasi main, validation, merge, push, dan archive task.
- [x] Guarded/HIGH/CRITICAL wajib approval eksplisit tetapi tidak dipaksa PR setelah approved.
- [x] Auto-PR workflow SB-002 tidak lagi menjadi default untuk task normal.
- [x] File/folder root non-canonical aman warning-only dan dapat ikut clean ZIP bila lolos denylist security.
- [x] Secret/env lokal/dependency/build/cache tetap tidak masuk clean ZIP.
- [x] `task:finish` membuat clean ZIP terbaru otomatis setelah main berhasil dipush.

## Plan

1. Satukan ownership menjadi COORD/FE/BE.
2. Hilangkan status/WIP/QA handoff yang tidak perlu untuk solo workflow.
3. Pertahankan branch per task dan overlap guard untuk pekerjaan paralel.
4. Tambahkan `task:finish` untuk commit, sinkronisasi latest main, local validation, merge, push, dan archive dalam satu command.
5. Guarded/high-risk wajib approval eksplisit; PR hanya fallback manual bila repository rules menolak direct push.
6. Pensiunkan auto-PR workflow universal SB-002.
7. Longgarkan root-entry ZIP menjadi warning-only sambil mempertahankan secret/build/dependency denylist.
8. Update tests/docs dan jalankan validation aktual.
