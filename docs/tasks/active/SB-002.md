## Objective

Membuat workflow Git harian user cukup `git add -A`, `git commit`, dan `git push -u origin HEAD`; sesudah push branch task, GitHub memvalidasi governance, membuat/reuse PR, menjalankan quality gate canonical, dan hanya melakukan merge otomatis untuk task non-guarded berisiko LOW/MEDIUM yang memenuhi seluruh syarat.

## Acceptance Criteria

- [x] Push ke branch canonical `*/SB-xxx-*` memicu `Quality` read-only.
- [x] `task:check` berjalan di GitHub dengan branch/base eksplisit pada push task branch.
- [x] `Task Submit` hanya berjalan melalui `workflow_run` setelah Quality PASS dan tidak checkout/execute kode branch dengan token write.
- [x] Workflow membuat PR baru atau memakai ulang PR terbuka untuk branch yang sama.
- [x] Privileged workflow membaca guarded-path registry dari `main` dan menolak task card yang menyatakan non-guarded saat guarded path berubah.
- [x] Exact tested SHA dan base `main` diverifikasi terhadap current branch/PR head sebelum merge; branch yang tertinggal dari main tidak auto-merge.
- [x] Auto-merge hanya diizinkan bila `Guarded=NO` dan risk `LOW/MEDIUM`; guarded/HIGH/CRITICAL tetap manual.
- [x] Guarded/HIGH/CRITICAL selalu berhenti pada PR setelah quality PASS dan membutuhkan merge/approval manual.
- [x] Repository rules tetap authoritative; kegagalan create/merge PR membuat workflow gagal tanpa mengubah `main`.
- [x] Tidak ada perubahan schema, auth, API contract, saldo, backup/restore, dependency, atau runtime finansial.

### Known Risks

- GitHub repository setting dapat membatasi `GITHUB_TOKEN` untuk membuat/merge PR. Workflow harus gagal tertutup bila permission tidak tersedia.
- Auto-merge yang terlalu luas berisiko melewati review; karena itu guarded dan HIGH/CRITICAL selalu manual.
- Auto-created PR dengan `GITHUB_TOKEN` tidak diandalkan untuk memicu workflow PR lain; Quality sudah lulus lebih dahulu pada push exact head SHA.
- Privileged `workflow_run` tidak boleh checkout/execute branch code; perubahan desain ke arah tersebut harus dianggap security regression.
- Auto-merge juga ditahan bila canonical guarded path berubah atau branch tertinggal dari `main`, walau task card mencoba menyatakan risiko rendah.
- Task card tidak dimutasi otomatis setelah Quality PASS agar head SHA/check tidak menjadi stale; COORD wajib melakukan post-merge reconciliation pada lifecycle task.
- Full Node 24 quality gate belum dapat dijalankan di sandbox karena dependency install terblokir registry internal.
